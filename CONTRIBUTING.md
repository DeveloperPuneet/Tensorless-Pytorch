# Contributing to Tensorless-PyTorch

Thanks for your interest in contributing to **Tensorless-PyTorch**! 🚀

Tensorless-PyTorch aims to make neural-network training simpler by letting Tensorless automatically decide model architecture, parameters, and training configuration while using PyTorch as the underlying training engine.

## 🛠️ Getting Started

1. Fork the repository.
2. Clone your fork:

```bash
git clone https://github.com/DeveloperPuneet/tensorless-pytorch.git
cd tensorless-pytorch
```

3. Create a virtual environment:

```bash
python -m venv .venv
```

Activate it:

**Windows**

```bash
.venv\Scripts\activate
```

**Linux/macOS**

```bash
source .venv/bin/activate
```

4. Install the project:

```bash
pip install -e .
```

5. Make your changes and test them locally.

## 💡 What You Can Contribute

Contributions are welcome in areas such as:

* 🧠 Automatic architecture selection
* ⚙️ Hyperparameter and training configuration
* 🚀 Training performance
* 🐛 Bug fixes
* 📚 Documentation
* 🧪 Tests
* 💻 PyTorch integrations
* 💡 New supported tasks and datasets

## 🔀 Pull Requests

Before opening a PR:

* Keep changes focused and easy to review.
* Follow the existing project structure and coding style.
* Add or update tests when appropriate.
* Update documentation if your change affects the public API.
* Make sure existing functionality still works.

Please explain **what you changed, why you changed it, and how you tested it** in your pull request.

## 🐛 Reporting Issues

When reporting a bug, include:

* Python version
* PyTorch version
* Tensorless-PyTorch version
* Operating system
* Minimal reproducible example
* Full error/traceback when possible

For feature requests, explain the problem the feature would solve rather than only suggesting an implementation.

## 📜 Code of Conduct

Please be respectful and constructive when interacting with other contributors.

Harassment, personal attacks, spam, and intentionally disruptive behavior are not welcome.

## ⭐ Before Contributing

Tensorless-PyTorch is actively evolving. Some APIs and internal systems may change as the project develops.

If you're planning a large change, **open an issue first** so we can discuss the approach before you spend significant time implementing it.
